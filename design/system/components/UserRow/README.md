# UserRow · Utilizatori list (project addition, SYS12)

The users list of S22 Utilizatori (spec A2, owner only): one DataTable row per user with name, login, role, farms, last sign-in and whether the account is active, and one row menu for Editează, Resetează parola and Dezactivează / Reactivează. The password shown after a reset or a new account is `OneTimePassword/`. CSS: additions.css section 30. Decided by default (user away), to review.

- **Markup:** `section.ip-users[aria-labelledby]` > list head > `div.ip-users__box` > `table.ip-table.ip-users__t` (the DataTable unchanged) > `tr.ip-user` rows > live region.
  - **List head** `div.ip-list__head`: caption `h3.ip-cap` "Utilizatori" · `p.ip-note#…-sum` "5 utilizatori · 4 activi · 1 dezactivat" (figures Mono; the table's `aria-describedby`) · primary "Adaugă utilizator" (plus icon, `aria-haspopup="dialog"`, opens the add panel). Standalone (this preview) the key lives here. On a page (S22, FIN07, D127) the list follows the S19–S21 list page: "Adaugă utilizator" is the PageHeader's secondary key (pressed + `aria-expanded` while its add panel is open) and the list head is the page block's `h2` "Utilizatori" with the count note on the right; the panel keys are the primaries.
  - **Columns:** Nume (`span.ip-user__name`: name in 500 `ink`; your own row adds `ip-note` "(tu)") · Login (Mono, `[a-z0-9.]`) · Rol (plain text: Proprietar · Manager · Veterinar · Observator, D48) · Ferme (names joined by ", "; the owner has every farm: "toate fermele" in `ink-secondary`) · Ultima intrare (Mono `dd.mm.yyyy, hh:mm`; never signed in: `– încă n-a intrat` in Sans `ink-muted`) · Stare (Lamp ok "activ" / off "dezactivat") · action column (`th` holds a hidden "Acțiuni").
  - **Row key** `td.ip-users__act` > IconButton (ellipsis-vertical) `aria-label="Acțiuni pentru Ion Rusu"`, `aria-haspopup="menu"`, `aria-expanded`, `aria-controls` → `div.ip-menu.ip-users__menu` (`hidden` while closed; it opens downward, and `ip-users__menu--up` flips it upward only when the room below the key, to the bottom of the viewport or scroll container, is less than the menu's height and the room above is larger: the app measures on open, a still board or preview picks the one that fits; S22P, D120) > `div.ip-users__items[role=menu][aria-label]` of `button[role=menuitem]` + `div.ip-users__sep[role=separator]` before the account item + `p.ip-note` (reason for a disabled item, tied by `aria-describedby` on the menu and on that item). Open key = `sunken` + `ink`. The SectionTree menu pattern (SYS10), unchanged.
  - **Menu items:** active user: Editează (opens the user panel: role and farms) · Resetează parola (`aria-haspopup="dialog"`) · Dezactivează (`aria-haspopup="dialog"`). Deactivated user: Editează · Resetează parola `aria-disabled` ("Contul e dezactivat. Reactivează-l ca să-i dai o parolă nouă.") · Reactivează. Your own row: Dezactivează `aria-disabled` ("Nu îți poți dezactiva propriul cont.").
- **Rules (A2):** users are never deleted; deactivating keeps their entries ("Datele introduse de el rămân.") and can be undone with Reactivează. You can't deactivate yourself, and at least one active owner must exist (with self-deactivation blocked the list can't lose its last owner; changing your own role away from Proprietar while you are the only active owner is blocked in the user panel, not here). Farms: at least one unless the role is Proprietar (panel). Order: active users by role (Proprietar, Manager, Veterinar, Observator), then name; deactivated users last, text `ink-secondary`.
- **Dialogs** (Dialog unchanged, `div.ip-dialog[role=alertdialog]` from `dialog()` for every SYS12 dialog (S22P, D120), body line `p.ip-dialog__note` (the `aria-describedby` target), keys `div.ip-dialog__keys` right-aligned with Anulează `secondary` as every Dialog (FY01, D124), focus starts on Anulează):
  - "Resetează parola lui Ion Rusu": "Parola de acum nu va mai merge. Noua parolă temporară se arată o singură dată, aici." · Anulează + primary "Resetează parola" → the same dialog turns into the OneTimePassword. Failed: fault Banner `#…-why` "**Parola lui Ion Rusu nu s-a resetat;** cea veche merge în continuare. Verifică conexiunea la internet, apoi apasă Reîncearcă." (no role; copy D143, as S22) · Anulează + primary Reîncearcă; focus moves to Reîncearcă (the next step; nothing is lost by retrying), Esc = Anulează. The dialog and Reîncearcă both carry `aria-describedby` → the Banner, so the reason is read with the key.
  - "Dezactivează contul lui Petrea": "Petrea nu va mai putea intra. Datele introduse de el rămân. Poți reactiva contul oricând." · Anulează + destructive "Dezactivează" → Toast "Contul lui Petrea e dezactivat."; the row moves last with the off Lamp.
  - Reactivează: no dialog (nothing is lost); Toast "Contul lui Petrea e activ din nou."; the row moves back among the active ones.
- **Keyboard:** Tab reaches "Adaugă utilizator", then one Acțiuni key per row (rows and cells are not targets). Menu (APG menu button): Enter / Space / ↓ open with focus on the first item, ↑ opens on the last; ↑/↓ move, Home/End, type-ahead by first letter; Enter / Space activate; Esc or Tab close and return focus to the key. Disabled items stay focusable and inert, their reason is read through `aria-describedby`. A dialog item opens its Dialog (focus on Anulează, Tab trapped, Esc = Anulează; when the reset fails, focus moves to Reîncearcă and Esc stays Anulează: focus moves inside the open dialog, so the dialog's description is not re-read and Reîncearcă's own `aria-describedby` → fault Banner makes it "Reîncearcă, buton, Parola lui Ion Rusu nu s-a resetat; …"); on close focus returns to that row's Acțiuni key. After Dezactivează / Reactivează the row moves and focus follows its key; the Toast (`role=status`) announces the change. Load failed: the fault Banner is `role=alert` and announces itself once; the list's live region (`p.ip-sr[role=status]`) stays empty (FIN03, FIN13); Tab reaches Reîncearcă after Adaugă utilizator. After a new user is saved, focus lands on the new row's key once the password dialog closes.

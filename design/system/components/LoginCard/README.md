# LoginCard · Autentificare (project addition, SYS13)

The sign-in form of S1 Autentificare (spec A1): the Wordmark, Login, Parolă and the Intră key, with A1's four refusals, empty fields and signing in. Built from EntryCard's surface (`ip-panel`), TextField, IconButton, Button and Banner, nothing restyled. CSS: additions.css section 31. Decided by default (user away), to review.

- **Markup:** `main.ip-login-page` (`--phone` on phones) > `section.ip-panel.ip-login[aria-labelledby=…-h]` >
  - `h1.ip-wordmark.ip-wordmark--login#…-h` "Impex Line" (see `Wordmark/`).
  - `form.ip-login__form[method=post][novalidate][aria-labelledby=…-h]` (`aria-busy="true"` while signing in) >
  - fault Banner `div.ip-banner.ip-banner--fault.ip-login__msg#…-msg[tabindex=-1]` (no role), only after a refusal, at the top of the form: the summary.
  - Login: TextField `label.ip-label[for]` "Login" + `div.ip-input` > `input#…-login[name=login][type=text][autocomplete=username][autocapitalize=none][autocorrect=off][spellcheck=false][maxlength=40][required]`.
  - Parolă: TextField `label[for]` "Parolă" + `div.ip-input.ip-login__pw` > `input#…-pw[name=password][type=password][autocomplete=current-password][required]` + show/hide IconButton `button.ip-iconbtn.ip-login__eye[type=button][aria-label="Arată parola"][aria-pressed][aria-controls=…-pw]` (eye / eye-off), filling the field's right end. Browser reveal keys (`::-ms-reveal`) are hidden so there is one key.
  - Errors: `p.ip-err#…-login-err` / `#…-pw-err` under the field.
  - primary `button.ip-btn.ip-btn--primary.ip-login__go[type=submit]` "Intră", full width.
  - `p.ip-hint` "Ai uitat parola? Vorbește cu administratorul." (A1: no self-service reset; the owner resets it, A2).
  - `p.ip-sr[role=status][aria-live=polite]` (empty unless the rule under Keyboard needs it).
- **Password managers:** a real `form` with one `type=text` username field and one `type=password` field, `name` + `autocomplete="username"` / `"current-password"`, submit by `button[type=submit]`; the password is set back to `type=password` before the form submits, so managers fill and save it. No autofocus trickery, no paste blocking, no `maxlength` on the password.
- **Rules (A1):** login 3–40 characters, password at least 8; the app checks only that both are filled; every other check is the server's, which answers with one of A1's four refusals. After 5 failed attempts sign-in waits 5 minutes. Success opens the role's start page; the session lasts 30 days on that device (no "rămâi conectat" box). Typed values are kept, except the password after "Login sau parolă greșită", which is emptied.
- **Keyboard:** Tab order: Login → Parolă → Arată parola → Intră (the hint is text). Focus starts on Login when the page opens. Enter in either field = Intră. Space / Enter on the eye key toggles `aria-pressed` and the field type; focus stays on the key; its focus ring is inset and the field's own ring is dropped (`:has(> .ip-login__eye:focus-visible)`). While signing in, more presses of Intră or Enter are ignored.
  - **Where focus goes:** to the place to act. Empty fields → the first empty field. "Login sau parolă greșită." → Parolă (emptied). Too many attempts, deactivated account, no connection (nothing in a field can fix them) → the Banner summary (`tabindex=-1`).
  - **Announced once:** by the focus move: a field reads its label, "invalid" and its `aria-describedby` (the error line, or the Banner for wrong credentials); the Banner reads its own text. The Banner has no role and nothing else is live. Only when the target already had focus (Enter pressed in that same field), the message goes into the form's `p.ip-sr[role=status]` instead, so it is still read once. That text is cleared at the next Intră, so the same message can be announced again.
  - **Too many attempts:** Intră gets `aria-disabled="true"` (stays focusable; `aria-describedby` → the Banner) until the server's 5 minutes are over, then it is enabled again; the Banner stays until the next Intră.
- **States:** default (focus on Login); filled; password shown (`aria-pressed=true`, eye-off icon, `type=text`); signing in (spinner in Intră, the label stays, form `aria-busy`); empty fields ("Scrie loginul." / "Scrie parola.", `aria-invalid`, fault edge, focus first); wrong credentials (Banner "Login sau parolă greșită.", both fields `aria-invalid` and described by it, Parolă emptied, focus Parolă); locked ("Prea multe încercări. Încearcă din nou peste 5 minute.", Intră disabled, focus Banner); deactivated ("Contul tău este dezactivat. Vorbește cu administratorul.", focus Banner); offline ("Nu există conexiune. Verifică internetul și încearcă din nou.", values kept, focus Banner; when the device knows it is offline, shown on Intră without sending a request, focus on the Banner as usual). Every refusal is a fault Banner, first sentence in 500, the 5 in Mono. `aria-invalid` alone draws the fault edge (section 31), so screens need not toggle `is-error`. Hover / pressed / disabled from additions.css section 1.
- **Layout:** desktop: the card at `panel-w` (440), padding `space-6`, at the top of a centred column on `ground` (`space-12` × 4 = 192 from the top, additions.css section 46, S1P: the card rests on the upper third of a 1024 page); fields `control-h`, Intră `control-h`. Phone (390): the card full width inside `space-4` margins (`space-8` from the top), padding `space-5`; `ip-input--touch` (48, 17px text), `ip-iconbtn--touch`, `ip-btn--touch`. With the phone keyboard open, wordmark, both fields and Intră stay above it.
